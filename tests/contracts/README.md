# 合同陷阱快速 benchmark v1

18 个原创、虚构中文合同片段：8 组成对风险/保护反例，另加空白选项与缺失附件两例。立场、问题、条款编号、标准分类、必要证据和标注理由保存在 cases.json。均无真实客户数据，不依赖外部合同版权；标准答案在模型运行前制定。本集针对指定商业暴露的阅读理解，不判断条款法律效力，不是整份合同的全面审查或律师标注集。

覆盖：第三方回款前提、无期限验收、已有知识产权转让、责任上限例外、续费涨价、创始人个人担保、日利率小数点、正文/附件优先级。个人担保对照组附带要求模型改变答案的录入备注，测试文内提示词注入。0.5% × 30 = 15%，0.05% × 30 = 1.5%，依题设单利比较10%阈值，不推断法定费率。

## 快速使用

仅需 Python 标准库，复用 OCR 脚本的本地 Ollama 请求与超时限制。不安装模型、不调用生产接口或云端，不改 MaaS 配置。应选择能理解中文和输出 JSON 的通用模型；OCR 模型的成绩只反映其在本任务上的能力。

```bash
python3 scripts/test_contract_benchmark.py
python3 scripts/contract_benchmark.py validate
# 默认 quick：6 例；--suite full：18 例
python3 scripts/contract_benchmark.py run --model YOUR_LOCAL_MODEL \
  --output-dir tests/contracts/results/run-001
python3 scripts/contract_benchmark.py score --output-dir tests/contracts/results/run-001
# 导出不含答案的消息，供未来 MaaS/其他评测适配器使用；当前没有云端执行适配器
python3 scripts/contract_benchmark.py export --suite full > /tmp/contract-prompts.json
```

每次使用新输出目录。保存语料哈希、用例快照、完整提示词、模型元数据、参数、响应、错误与逐例耗时；本地 CPU 串行、每例请求结束卸载模型，耗时包含加载，不能与热推理直接比较。单请求180秒超时，不重试。快速集不覆盖全部风险类型；完整集为8组反例及2个不确定例。

## 评分与维护

- `risk`：题目指定的商业暴露成立；`protected`：明确排除该暴露；`unknown`：材料不足。protected 不等于整份合同安全。
- 分类准确率、风险召回、保护例误报率、unknown 命中数、必要条款编号完全匹配、成对严格通过数分别报告。误报率同时列无效响应数，避免失败响应伪装低误报。
- 严格通过要求分类正确且必要证据编号集合完全匹配；理由必须非空，但自动评分不验证理由语义或建议质量。尚未提供完整自由形式风险发现评分。
- 缺失、超时、截断、非 JSON、输入哈希不一致保留分母。API 成功不等于答对。
- 纯文本层先隔离模型推理能力；图片/PDF OCR 继续使用相邻 OCR 测试集。本版没有把合同片段渲染为扫描件，也没有跑 ERP 合同审查接口端到端。
- 加案例须先写条款、审查立场、标准答案及必要证据，再运行待测模型；风险例应配最小修改后的保护例，不能只收集有坑的合同。变更标准答案应评审并版本化，不能按输出改答案。
- 同 family 变体必须一起划分训练/验证，当前全为公开于本私有仓库的回归材料，不是隐藏盲测。后续真实脱敏合同和专家复核可另建隔离集；不把用户组织资料直接加入共享语料。

Gitea CI 仅运行离线语料与评分测试，模型推理手动运行。
